# ADR 0020: minimal R0 engineering control

Status: written public interface before implementation, 2026-10-05.

EngineeringControl in the existing Self-Improvement module owns generate, checkFeatureMap, updateFeatureMap and garden. The CLI parses the existing registered leaves and projects generated contracts. No service, privilege, caller executable, SQL, root, provider endpoint or model job is introduced.

Generate accepts the registered kind, lowercase kebab name, owner/provider/operation selectors and plan flag. It derives each template only from the four exact source hashes in K4a reference-verification.json. Source changes or absent verified receipts block that template. Connector uses the empty external fake reference; the first tool supports the actual canonical Ops status owner; skill uses the local canonical skill; migration uses the disposable Ops marker pattern and is never applied by generation. Broader production adapters and full runtime/publishing behavior stay at their assigned R1 cards. Source-owned contracts, registrations and feature-map patches accompany generated files.

Plans contain relative paths, before/after digests, exact content, template digest, owner, feature/AT IDs, prerequisites and before/after inventory digests. Apply refuses existing targets, duplicate names, symlink escapes, paths outside the trusted checkout and protected trees. It atomically writes only new owned files and authoritative registration/map changes; failure removes only that attempt's unchanged new files and restores its own metadata bytes. No overwrite, force, download or migration execution is exposed.

Map checking compares source declarations, complete command metadata, exact source-bound AT assertions and the deterministic canonical table. It rejects missing, orphan, duplicate, changed assertion/digest and dangling requirement, entry, interface or file links. Future NOT_IMPLEMENTED declarations retain their source-assigned release and written owner interface. Update produces a plan or exact atomic patch; repeated coherent update/check is byte-identical. The checker never writes.

Gardener scan dispatches the existing fixed static/codegen policy gate, adds generator/map checks and records finite findings and correction rungs. It performs no semantic model job, incident delivery, repair, schedule, publication or deployment. R0 fix mode remains unavailable until its assigned owner gates.

Verification uses public toy commands with temporary owned source/OS fixtures. AT-cli-7 mutates each linkage independently and expects an exact refusal. AT-cli-8 checks complete future declarations, deterministic update/check and protected/path refusal. AT-hermes-config-101 runs existing compiler/boundary/comment/type/DTO/drift/INT negative cases plus valid generator fixtures and map cases through the CLI. No private helper or internal collaborator is mocked. Full AT-cli-25–27 runtime/SIM/publishing stays pending R1.

The current managed execution profile denies the kernel pressure query and Git metadata writes. Fresh available-memory readback passes the job-plus-margin requirement; pressure remains explicitly unknown. Static/source engineering commands can continue. Physical stack admission and current-profile runtime receipts retain the missing OS-measurement prerequisite, and uncommitted coherent source remains in the workspace until Git writes are permitted. No permission bypass or substituted normal-pressure observation is used. The earlier four reference receipts remain historical proof for the unchanged template source hashes.
