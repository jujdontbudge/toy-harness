# R0 kitchen foundation

The accepted architecture is Hermes plus the deep modules named in architecture-v3 and CONTRACTS. `architecture/modules.json` freezes the permitted public import graph. It is a build-time graph, not a deployed service inventory. Every owner gets one private workspace package and one public entry point. DTO definitions live only in `@toy/contracts`. Authority, evaluator, publisher and Secrets implementations belong outside ordinary packages under protected controls; their production installation and OS ownership remain pending R0.04–05.

The written interfaces are the owner operations in CONTRACTS and each module's Interface section. Scaffolds export no behavior and cannot acknowledge work, create permissions or claim readiness. New administrative behavior belongs to the existing Ops and Self-Repair owners, as cli.md §6 specifies. No new domain module is introduced. Removing an owner would move its durable state and policy obligations to its callers; removing the CLI would leave those behaviors intact.

Canonical amendments supersede architecture-v3's older vendor and cadence choices: Keychain replaces Bitwarden, local diagnostics replace Grafana Cloud, local connectors replace Composio, and full Sol/max/Fast review every 180 seconds remains authoritative. Historical SQLite and Plus references describe preserved predecessors. Neither is the new implementation target.

Node 24.21.0 and npm 11.19.0 were measured on this ARM64 macOS 26.7.1 host. Hermes and the old core are running and are preserved. TypeScript 6.0.3 is selected because typescript-eslint 8.71.0 supports versions below 6.1; the registry's latest TypeScript 7.0.2 falls outside that range. Zod 4.6.5 is the latest stable 4.x observed at bootstrap and is pinned only by the contracts owner. npm package-lock records the integrity of the exact package closure. Python 3.9 is only the isolated local static-tool environment; it does not replace Hermes's locked interpreter.

Primary references: [strict TypeScript](https://www.typescriptlang.org/tsconfig/strict.html), [checked indexed access](https://www.typescriptlang.org/tsconfig/noUncheckedIndexedAccess.html), [typescript-eslint compatibility](https://typescript-eslint.io/users/dependency-versions/), [dependency-cruiser](https://github.com/sverweij/dependency-cruiser/blob/main/doc/options-reference.md), [Zod JSON Schema](https://zod.dev/json-schema), [Ruff configuration](https://docs.astral.sh/ruff/configuration/). These direct checks are bootstrap dependency evidence, not an attested toy-research report. That separate research gate remains pending.
