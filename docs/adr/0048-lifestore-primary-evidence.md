# Life Store primary evidence and quote checks

Status: accepted source-phase boundary; CLI and whole-acceptance proof remain pending.

AT-lifestore-45 requires each selected Life Store component decision to carry versioned primary evidence and exact requirement quote mappings. Existing V1, V2 and V3 records and their readers remain in use. `EngineeringControl.checkResearch` is the canonical owner, and `ResearchDocumentOverlayV1` remains its fake external-document seam.

Add `ResearchComponentComparisonV4` as an additive record format. It carries nullable `sourceVersion`, exact UTF-8 `sourceContent`, a SHA-256 digest of those bytes, a byte span locating the version, primary quote byte spans, and requirement quote mappings. A null version remains schema-valid so the owner can return a semantic `PRIMARY_EVIDENCE_MISSING` finding. Version, digest and quote failures are checked against actual bytes. Requirement quote spans are checked against an exact safe read of the canonical `REQUIREMENTS.md` file and its full-file digest, and each requirement ID is bound to its own parsed requirement cell and byte span.

The existing `EngineeringControl` owner also exposes a narrow `canonicalRequirementQuotes` operation over an array of requirement IDs. It returns the V4 quote-mapping DTO slice using the same exact safe reader and parser. It accepts no path input and does not act as an oracle: the public `checkResearch` readback independently reparses the canonical file and validates every submitted quote, digest, ID and byte span.

The owner derives Life Store component scope from the existing requirement-group parser. It reads Life Store §2 requirement identifiers, direct `L` consumer tokens and case-insensitive whole-word `All` tokens, then unions only source-defined non-global register groups that map those requirements. The global 0.1, 0.2 and 0.10 quote mappings apply to every scoped component but do not assign component ownership. Repeated group mappings union for Life Store; the existing Ops duplicate-refusal behavior remains unchanged. No component-ID inventory is copied into code.

V4 records continue through the existing comparison gates. Exact quote/evidence checks do not satisfy account or region plans, research route and skill receipts, release gates, validations, or other existing requirements. The public owner checks every derived component but each diagnostic CheckView stays within its 2,000-character limit, reporting counts, exact failing IDs and deterministic aggregate digests rather than serializing all component records. Fixture-only primary bytes are not authenticated external research.

The assigned ten-case CLI matrix must cover the positive quote/evidence subcheck and one-at-a-time missing component, missing requirement quote, unsupported choice, missing version, wrong version, wrong digest, wrong primary quote, wrong requirement quote and missing validation. The full component decision can remain BLOCKED for unrelated existing gates. Global admission remains BLOCKED, wholeATsPassed remains empty, and acceptanceComplete remains false. No public build caller currently consumes the findings, so affected-build blocking remains unproven.
