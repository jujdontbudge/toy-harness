# Actual control filesystem denials

The existing Ops TestProbeControl owns one fixed control-filesystem-denial case for AT-authority-35. Registered CLI probes accept no path, executable, UID, GID, code or expectation. An already-root test controller creates a private root-owned case directory under the canonical control/protected-tests root and one disposable child scratch directory under the existing agent home. Caller identity is observed, never supplied by CLI JSON. Ordinary caller-owned worlds remain separate from root-owned control test worlds. The root controller uses only its protected fixture index; the historical ordinary-caller bootstrap journal keeps its root refusal and is never created or adopted by root.

The fixed compiled denial entry and its source assertion/artifact manifest are copied into the protected case directory before execution. The reviewed entry starts as root, replaces inherited supplementary groups with the measured dedicated agent GID and then drops real/effective GID and UID before any target operation. It reports the actual process identity/groups, a successful permitted scratch write and all six fixed OS-denial attempts. The parent validates the canonical result, exact UID/group set, denied errno and independent root canary/file/directory readbacks. Only newly allocated nonsecret test targets are touched. It removes only its declared scratch children; test manifests and root canaries are retained as evidence.

The entry has only Node built-in imports and generated contract type imports. Its private argv comes from the fixed registered owner, not the caller. No service, profile, live credential, network provider, GUI, sudo policy or existing control file is changed. This first actual-UID case is diagnostic evidence; complete protected evaluator/launcher registration and unfiltered whole-assertion certification remain pending. AT-authority-36 and wider MCP/GUI/IPC matrices are separate requirements, not implied by six filesystem denials. Swift remains deferred to R3.
