# K3 native test-stack lifecycle

Status: written interface and bounded implementation plan only. No controller, launcher, signature, database or stack has been created. ADR 0006's runtime predicates remain unresolved. This extends existing Ops and the registered test controller; it creates no permanent CLI service, account, gateway, production datastore or privileged path.

## Public ownership

`OpsTestStack.up(TestStackUpInputV1, OpsControlContextV1)` admits a durable request and assigns the stack UUID. `OpsTestStack.down(TestStackDownInputV1, OpsControlContextV1)` fences one generation, archives permitted evidence and stops only resources that the same generation demonstrably owns. Their data composes canonical `OperationRef` and CLI §4.4's `TestStackOperationV1`, `TestStackViewV1` and `TestStackTeardownV1`. Inputs normalize only the existing CLI flags: release, requestId, registered world, clock/model selections and bounded wait; no path, identity, credential, SQL or executable is accepted. A changed request under the same requestId conflicts; an identical retry returns the original operation.

The existing registered test controller owns `runRegisteredProbe` / `registeredProbeStatus` and test-clock operations. Probe IDs are source-indexed CLI-rung acceptance IDs, with fixed cases and assertion closure selected by a sealed registry. Cases are not new acceptance IDs. A focused case reports its subset and cannot pass the whole source assertion. The CLI has no database role, fixture loader, oracle or process-launch privilege. It calls the owners' public adapters and emits their validated safe receipts.

R0's initial world is registered as `r0-bootstrap` and contains only feasibility components, fake external providers, fake model and a fake clock. A requested supported model lacks admission until R0.01; it returns a prerequisite result and makes no semantic send. Other releases and worlds remain unavailable until their real owner closures are admitted. Unavailable R1 owners are not substituted. Real-clock mode requires its own admitted closure; fake-clock operations cannot silently change that mode.

## Controller and transport

One transient Ops controller owns one admitted stack generation across separate CLI invocations. Its process, actual effective UID/GID, incarnation, artifact and private control endpoint are recorded in the stack manifest. It is an owned temporary test process, under an ephemeral caller-UID launchd job registered by Ops, with no permanent installation or service-account claim. The controller stays in the foreground and handles SIGTERM. The job has a fixed per-stack label and an owner-derived user domain whose existence is measured before admission; it cannot create or use a system domain. Launchd is the external supervisor. A real-time lease, pressure checks and startup/teardown recovery are additional owner policy. It may never leave a database or helper without a recorded owner or adopt an arbitrary existing process.

CLI-to-controller transport is a fixed typed protocol over the stack's owner-only Unix endpoint outside the sandbox. The endpoint path is derived by Ops from the allocated stack UUID; callers supply neither it nor a URL. The native transport must authenticate kernel peer UID/GID and bind it to the recorded owner before parsing an operation. Node reachability alone is insufficient authentication. Every request, including status/show, also requires the existing evaluator/controller authorization capability and a current independently sealed stack/generation attestation; peer credentials alone confer neither. Those originate in the registered owner transport context and are never caller arguments or public receipt fields. A random port, ambient token, caller principal or asserted PID is not an alternative. Missing peer verification, owner capability or current attestation fails closed. This is private test IPC, not a new permanent service endpoint.

The controller owns inherited framed stdin/stdout pipes to the signed native launcher for the entire stack lifetime. Later CLI invocations use the attested controller endpoint; they cannot reuse a departed invocation's pipe or address the launcher directly. Frames have a fixed version, stack/generation/request binding, bounded length and a closed opcode enum. Complete request/result schemas belong to Contracts. No opcode accepts arbitrary code, argv, environment, shell, SQL, host path, endpoint, UID, proof or expectation. Stdout carries only validated protocol; separately bounded stderr is sanitized before archival.

Initial opcodes are restricted to readiness/identity, fixed private-cluster startup/status/shutdown, registered case dispatch, clock state/barrier and bounded evidence export. A fixed registered fake-provider/model request crosses the controller's external-seam broker; the sandbox gets no network entitlement. Protected expected results and independent ledgers remain outside the target bundle/container. The controller validates exact bindings and artifact freshness for each operation, monitors the complete child tree, and fences stale or superseded generations. The launchd job remains until verified teardown and ownership reconciliation are complete. Unexpected controller death triggers recovery through the same fixed supervisor, which fences requests and reconciles recorded PID/incarnation ownership before stopping or resuming anything. Neither process-group cleanup nor a controller-local lease substitutes for measured descendant cleanup; PostgreSQL session/process-group behavior is an explicit failure/recovery cell. No long-lived helper starts before this external supervision is admitted. A bounded one-shot native-entry feasibility child may terminate within the current up operation without creating a persistent stack.

## Native artifact and private database

The selected mechanism is the App Sandbox parent/inherited-child arrangement from ADR 0006. Parent entitlement is only app-sandbox; children have exactly app-sandbox plus inherit. Hardened runtime/library validation remains enabled. No network, file-selection, temporary exception, app-group, Keychain, TCC or JIT grant is added. Node uses `--jitless`. Every other inherited descriptor is closed before helper exec. Environment is a fixed allowlist with no live home/configuration or credentials.

The registered base bundle identifier is `net.toy.bootstrap`. A per-stack materialization has a deterministic identifier suffix derived from its full stack UUID and an independently verified collision/ownership check. Each materialization seals the fixed Info.plist, launcher and complete helper closure with local ad-hoc signatures. Materialized content, CodeDirectory, entitlements, dependency-lock, SDK and runtime digests are in the immutable manifest. The target cannot select or change these bytes. Existing unowned bundle/container paths are never reused or removed. Separate stack containers are required; a shared container containing another stack is inadmissible.

The controller verifies the exact signature and entitlement dictionaries with codesign and native Security APIs immediately before exec. A signature is static identity evidence only. Native entry, inherited-child identity and all required denial/readiness cells need real CLI receipts. Early abort or a denied pinned interpreter blocks the design; there is no unconfined helper, sandbox-exec, entitlement relaxation or production service fallback.

PostgreSQL 17.11, database `toy` and schema `pgboss` run only as recorded inherited children inside the stack sandbox. `listen_addresses` is empty. Node's real database client uses a private socket inside that same container. Socket path UTF-8 length must fit the actual macOS limit; Ops derives a short owned directory and checks its real path, ownership and manifest binding. No TCP listener or socket outside the container substitutes for failed AF_UNIX feasibility. The exact server/client socket behavior with absent network entitlements is an explicit native admission predicate. It has not been established.

Trusted staging builds and seals the pinned closure before runtime admission; no package download occurs at startup. Bootstrap staging is part of K3's explicit kitchen exemption. Future R0/R1 additions follow the four K4 generators. A native feasibility failure is preserved as a measured prerequisite/failure with safe receipts and triggers design recovery; it cannot become an AT PASS.

## Manifest and state

Generated internal manifest schemas must bind: stack UUID/generation; durable request and operation; first-release/world/case registry; source/release/control/schema/fixture/artifact digests; actual owner and launcher identities; immutable native/helper closure/signatures/entitlements; derived private resources and endpoint owner/mode; exact allowed operations and inherited handles; fake provider/model/clock origin; pressure/headroom/one-heavy-work lease; real expiry; and owned process-incarnation references. Capability bytes and private expectations are absent from public views.

Controller request journals and attestations live only in the allocated owner-only temporary control root. They are not a new production datastore. Writes are atomic, bounded and generation-fenced; recovery verifies ownership and artifact identity before resuming any operation. The controller cannot certify a target-written attestation. Sandbox descendants cannot read or write this control root. Independent actual service ownership/permissions remain separately pending R0.04–05; a caller-UID bootstrap receipt proves no `_toy_agent` gate.

Admission is reserve → verify artifacts/identity/resources → allocate private owned roots → launch signed tree → verify native/container/database/fake-provider readiness → publish the safe manifest view. Readiness includes every mandatory cell; incomplete admission remains ready=false. Failure archives allowed evidence and reconciles/cleans only owned resources. The public operation retains its stable identity even when no usable stack is produced.

Teardown is fence → checkpoint → stop new work → reconcile uncertainty → stop the verified tree → independently read back stopped processes/private resources → archive → remove only proven-owned disposable outputs. Unknown ownership, incarnation mismatch, symlink escape or unresolved work makes complete=false and preserves unresolved references. No caller-selected process is killed and no unowned path is deleted. A later retry continues the same teardown operation.

Fake-clock advances use positive bounded elapsed durations, at most seven virtual days, while admission/leases/waits/resource/usage freshness remain real monotonic time. A barrier reports settled/pending/blocked with unmet references; virtual passage does not fabricate review, quota or production elapsed capacity. Cadence coverage retains the twelve-state denominator and labels fake-model/exact/projected/real arms distinctly. No accepted Turn Review exists in this initial fake-only closure.

## Implementation cards and proof

The initial native-entry receipt is strictly `{protocol:"toy.bootstrap-native.v1",parent:NativeProcessIdentityV1,child:NativeProcessIdentityV1|null,entered:true,inheritedChildEntered:boolean,containerHomeReady:boolean}`. Process identity is `{pid,parentPid,uid,gid,birthSeconds:UInt64String,birthMicroseconds:integer[0,999999]}` read from kernel process metadata, preserving the exact incarnation sample. Entry/container existence does not prove containment, service UID, denial, resource or readiness predicates. No native receipt accepts input or chooses a path.

The first generated public boundary uses the exact CLI §4.4 operation/stack/clock/probe compositions and canonical Ops `OperationRef`. `evidenceLocation` is the existing opaque UUID `ArtifactRef` from Hermes §5.1, registered by the evidence owner; it is never a filesystem path. `ArtifactBindingV1` keeps its four distinct digest fields. All source-indexed CLI-rung AT IDs are compiled from `tests/acceptance-index.json` by the sole Contracts generator, with their assertion hashes and first releases; this is an ID inventory, not an executable or accepted case inventory. Case IDs require a separate fixed owner registration and an admitted closure before dispatch.

Normalized up input is `{release,requestId,world?,clock,model,waitMs}`; down is `{requestId,waitMs}` with the stack supplied only by authenticated context. Clock freeze is `{at,requestId}`, resume is `{requestId}`, advance is `{by,requestId,waitMs}`, and show has no fields. Probe run is the exact `{probeId,requestId,caseId?}`; probe show is `{operationId}`. Bounded wait is 0–120,000 ms. Clock elapsed-duration syntax permits day/hour/minute/second units and millisecond fractions only; the owner must enforce a positive total no greater than seven days before any change. Schema-valid syntax is not permission to skip that owner predicate.

Initial registered readiness IDs cover artifact signature, native entry, inherited child, filesystem/network/Keychain denial, cross-stack container identity/isolation/cleanup, PostgreSQL AF_UNIX, controller peer authentication, resource admission and cleanup. They are distinct from source AT IDs and never certify a whole assertion. Initial case names are fixed feasibility selectors, with no caller-controlled fault data. No launch is admitted merely because these generated names exist.

1. Generate canonical operation/stack/clock/probe inputs/results, fixed world/case IDs, native frame and manifest types. Compile each public owner boundary before implementing dispatch. Pending future CLI schemas stay discoverable without claiming implementation.
2. Implement trusted staging and the minimal signed native entry/child/denial feasibility cells. Drive admission only through the compiled `toy stack up` path. Retain entry/identity/signature/denial and cleanup evidence; failure leaves the stack unavailable.
3. Prove pinned private PostgreSQL AF_UNIX operation in the same sandbox. Then add the temporary Ops lifecycle/peer-authenticated endpoint, durable requests, real-clock lease/pressure supervision and restart/teardown readbacks. A process surviving CLI exit is accepted only when its owner and lifetime are attested.
4. Add the registered clock/probe transport and largest-interface CLI fault matrix, including stale/substituted manifests, swapped stack paths, wrong peers, unknown frames, interrupted controller, dropped pipe, unsupported inference and cleanup ownership. A registry-selected external fake supplies faults; no internal collaborator is mocked.
5. Exercise exactly the four K4a public references and derive K4 templates only from their verified digests/static/public receipts. Full assigned ATs and actual R0.04–05 identity/launcher predicates remain independently pending.

The written interface must be refined when machine evidence falsifies a proposed predicate. No current card availability, AT verdict, native containment, database persistence or deployment is inferred from this ADR.
