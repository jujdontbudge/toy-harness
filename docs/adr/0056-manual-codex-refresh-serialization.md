# ADR 0056: Observe manual Codex refresh serialization through public chat

Status: causal CLI RED reproduced; second source phase implemented, GREEN and whole acceptance pending.

AT-hermes-config-87 requires real concurrent auth operations, independent provider effects and fresh-process readbacks. Process overlap does not prove that a contender loaded the expired grant. Independently added Codex credentials live in their pool rows, while the pinned refresh path reloads singleton state. A genuinely preloaded contender can therefore repeat the consumed refresh request after waiting for the storage lock.

The actual `CredentialPool` owner exposes a bounded `refresh_dispositions()` snapshot. Each record contains exactly `expiredBeforeLock: boolean`, `pairChangedAfterLock: boolean`, and `disposition: refresh-invoked | reloaded-after-serialization`. The owner computes expiry before its refresh lock and compares the pair after synchronization under that lock. Credential bytes, hashes, claims and synthetic generations never leave this interface. The refresh-invoked record marks the owner entering the real refresher; it does not assert an HTTP send or success. A missing decision is represented by an empty list.

The existing `hermes chat --format stream-json` terminal result carries these records as `auth_refresh`. The emitter retains the real agent's credential pool and reads its public snapshot. The protected fixture parses that public result and forwards its records unchanged into the existing canonical concurrency result's required `refreshDispositions` field. The provider ledger remains the independent proof of actual HTTP sends. Only the isolated single-grant cell requests structured output; the original four-case matrix keeps its text interface. The reader requires exactly one actual terminal result with matching exit status and exact bounded owner records. It tolerates incidental non-JSON diagnostics but rejects malformed JSON records, and scans both complete captured streams for credential leakage. A parser rejection is PUBLIC_STREAM_RESULT_INVALID; CLI_EXCEPTION is reserved for the real public command raising.

An isolated subhome contributes a single-grant regression to the existing `refresh-first` case. Real profile creation, auth-add and auth-list establish one profile-owned synthetic grant. The fake provider issues the existing expired `rotated` generation for this subcell. Both real expired-chat processes stop at the existing external OS barrier before acquiring the fixed temporary profile `auth.lock`. The public list first warms the pinned owner's existing heal-clean cache. Only ordinary file identity and the original OS locking operation are involved; the fixture does not inspect private Hermes functions or observe successful lock acquisition.

Both scheduling barriers must be reached before the winner starts its provider request. The winner's refresh response is held at the existing provider seam. After release, the contender must report real pre-lock expiry, an in-lock changed pair and `reloaded-after-serialization`, with no provider refresh. Its old row was already loaded before the winner proceeded, so late scheduling cannot substitute a fresh initial load. The owner receipt rejects a barrier reached during earlier loading. Fresh public chat/list verify the latest accepted generation, and the original four-case matrix retains its original scope, add readbacks and crash cuts.

Existing CheckView prerequisites are bounded at 2,000 characters. The single-grant proof stores bounded per-child projections of the canonical public result and a compact combined predicate, with stream digests in existing artifact links. Child decisions expose at most two records plus the full count; the acceptance predicate still requires exactly one decision in each child. Fixed stages and allowlisted nonsecret error categories identify source/capture failures without messages or stacks.

Phase 1 added the public receipt and regression while leaving both manual-row resynchronization changes absent. The source-bound real CLI RED showed both preloaded owners reporting expiry, unchanged pairs and refresh-invoked, with one rotated-to-stale HTTP refresh each. Phase 2 now routes locally owned manual Codex rows through exact pool-row synchronization and reuses the existing changed-and-valid early return under the existing lock. A manual row whose ID belongs to borrowed_root_ids keeps its previous route; singleton-seeded and external-reference sources retain their previous behavior. The force flag, provider refresher, persistence and root merging are unchanged. The parent must collect source-bound CLI GREEN before claiming the duplicate-refresh fix works.

Serialized prevention does not claim that a delayed stale response was delivered or rejected. The existing `staleRefreshResponse` and `staleRefreshTokenRejected` fields remain `not-exercised`. Whole-AT acceptance remains pending until the assigned CLI evidence, protected identity requirements and all mandatory assertions pass. The real installed Hermes checkout and six frozen root pins remain unchanged; packaged patches apply only to the disposable candidate.
