# ADR 0027: R0 model admission and canonical accounting

Status: R0.06 canonical PostgreSQL schema and accounting owner verified through nine public CLI diagnostic checks. Actual protected provider binding, complete assigned ATs and deferred slot/wake integration remain pending. Evidence: `build/evidence/R0.06/accounting-runtime-verification.json`.

R0.01 requires a durable reservation before its one supported provider-send seam. Accounting belongs to Self-Improvement's `toy_si.budget_group`, `toy_si.model_call`, and `toy_si.quota_snapshot`. Ops owns the consumption policy and subscription-observation freshness. It has no entitlement counter or accounting database. The existing dependency direction lets Self-Improvement call the public Ops policy interface; Ops does not import Self-Improvement.

`ModelAdmissionPolicy.evaluate(input)` returns consumption eligibility and a reason, mode, and bounded retry time. It consumes the owner's canonical ledger projection and a normalized authorized quota observation. It issues no send permit. Fresh five-hour and weekly windows are recognized by duration, and either equality breach vetoes autonomous work independently of the other window. Missing, stale, malformed, unauthorized, or account-mismatched observations select the fixed eight-job UTC-day policy; a trusted, individually validated fresh window still vetoes when the overall source is unavailable or its other schema fields changed. Optional repair and replay remain paused under fallback. A future observation cannot count as fresh. Foreground consumption is accounted separately and never charged to that background count. Foreground stop judges retain the authenticated originating foreground class. Lease, restored-history, policy-binding, and upper-bound reservation checks remain distinct from provider entitlement. Only a threatened window contributes its reset to a reservation hold.

The accounting owner interface is `ModelAdmission.reserve(request)`, `ModelAdmission.claimSend(callId)`, `ModelAdmission.settle(settlement)`, `ModelAdmission.observe(observation)`, and `ModelAdmission.inspect(accountRef)`. Reserve must use one database transaction to bind call key, root budget, run/generation, account, route, policy, named windows/reset, expected cost and work class; count all reserved/attempted/uncertain autonomous calls for that UTC day across goals and restarts; acquire the single provider lane; and persist either the reservation or denial/wake. Call-key replay returns the existing outcome and cannot allocate another send. ClaimSend rechecks current policy and durably changes the native send count from zero to one before the physical provider call; a second claim fails. Only the trusted owner constructs the ledger projection and authenticated foreground provenance. A caller-supplied policy decision is never a capability.

Settlement retains uncertain charges. Cancellation or a local disconnect cannot release the lane without native terminal/cancellation acknowledgement. A settled model-call row is immutable; later corrections require a new settlement event. Observation cannot clear an unreflected reservation without evidence that provider usage includes it. Restoring older accounting requires conservative exhaustion until reconciliation. Actual role/database grants must preserve the canonical single writer; Hermes receives no database credentials.

The prepared owner uses the installed PostgreSQL client through one private, bounded Unix-socket adapter. Each mutation obtains the same transaction advisory lock. Reserve and claim compare the normalized prior projection inside a fresh READ COMMITTED statement after acquiring that lock, retrying a changed projection at most three times. Database constraints retain the independent single-lease and send-count limits. The client digest is pinned, authentication files and inherited provider settings are excluded, input travels over private stdin, and raw database errors never enter receipts. A monotonic quota observation sequence preserves arrival order when fake time is frozen.

Production construction requires the actual real and effective `_toy_review` UID and a fixed root-owned runtime configuration. The disposable constructor derives its database socket only from an already-owned, ready fake-model/fake-clock CLI stack and reads that stack's public clock. Neither constructor issues a provider-send permit. The admitted public CLI stack executed the real PostgreSQL 17 migration and accounting transactions after the execution profile changed. Nine diagnostic checks cover named equality thresholds, the eight-job fallback across a physical PostgreSQL restart and new goal, and missing/reordered known-window vetoes. Exact probe readbacks and clean owned-stack teardown are archived in the runtime evidence. That builder-owned database does not prove protected service-identity grants or the complete assigned AT matrix.
