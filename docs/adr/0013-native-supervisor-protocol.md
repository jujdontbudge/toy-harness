# Fixed bootstrap supervisor protocol

Status: implementation preparation. No executable owner admission, resource permit, durable operation, App Sandbox signature or native runtime proof is granted by this document.

The trusted native supervisor is the third fixed prepared asset. It uses Security's public validity and signing-information APIs and kernel process inspection, which the TypeScript control adapter cannot establish by parsing `codesign` text. Its only input is one bounded generated request on inherited descriptor 3. The request binds owner-assigned request, operation, stack and generation identities, the schema/build digests and the expected signed executable digests. It accepts no path, executable, argument, environment, entitlement, caller identity, resource override or expected failure. This private request is not a public CLI selector or an authorization token. The Ops owner must establish the durable journal, current generation and resource permit before supplying it.

The supervisor derives the parent and child paths from its own kernel executable location: sibling `ToyBootstrap.app/Contents/MacOS/bootstrap-parent` and `ToyBootstrap.app/Contents/Helpers/bootstrap-child` in the same newly allocated generation root. The supervisor sits outside the application bundle to preserve its strict resource seal. Parent Security validation covers the whole application bundle. No sandbox container is inspected or traversed. The bundle identifiers are `net.toy.bootstrap.stack.<lowercase-stack-uuid>` for the parent, that identifier plus `.child` for the inherited child, and `net.toy.bootstrap.supervisor` for the trusted supervisor. These are private bootstrap identifiers, separate from the R5 candidate identity.

For each role, validate all architectures, nested code, strict rules and restricted symlinks with network access disabled before reading signing information. Require the exact identifier, expected SHA-256 executable bytes, an ad-hoc signature with no team identifier, hardened runtime, no unrecognized signature flags and the exact entitlement dictionary. The supervisor has no entitlements; parent has only App Sandbox true; child has only App Sandbox true and inherit true. Hardened runtime enables library validation by default, and exact entitlements prohibit its disabling exception. The Security code identifier remains a distinct 20-byte identifier represented by 40 hexadecimal characters; it is never a SHA-256 artifact digest. Recheck all executable hashes immediately before spawn. These static checks do not prove sandbox enforcement or defeat a malicious process sharing the owner UID; production identity/file protections remain separate gates.

The supervisor spawns only the fixed parent using close-on-exec descriptor selection, `/dev/null` for input and error output, one bounded receipt pipe and a minimal fixed environment. The parent keeps its existing child identity/acknowledgment handshake on descriptors 3 and 4. The new parent receipt is `toy.bootstrap-native.v2`; after emitting it, the parent remains alive waiting on descriptor 5. The supervisor samples its direct child through the kernel, compares the complete PID/PPID/UID/GID/birth tuple and executable path, validates the live Security guest and its signing identifier against the static observation, then repeats the incarnation sample. It acknowledges through descriptor 5, then reaps the parent. Every wait uses a real monotonic deadline. A timed-out cleanup signals only a still-unreaped direct child and records uncertainty rather than inferring complete descendant/container teardown.

The generated supervisor receipt exports only bound identities, validated signature observations, validated entry and external parent identity, finite failure/exit classifications, stdout byte counts and direct-parent reap status. After reaping, stdout must end without trailing bytes. Parent stderr goes to `/dev/null`, so its byte count is unknown/null rather than an invented zero. Malformed input/output and raw stderr are not archived. Missing or mismatched observations remain absent. Child entry is independently observed by its trusted native parent; the supervisor's external sample attests the parent only. A reaped parent is not proof that all descendants or OS container metadata were removed.

`NativeBuildManifestV2` adds the supervisor artifact and source digest to the immutable build closure. Historical V1 generations remain readable and are preserved before replacement; V1 cannot satisfy the new runtime closure. Both prepared and signed hashes remain distinct, since signing changes executable bytes. The builder does not sign or execute these assets. The public Ops result remains unavailable until durable ownership, resource accounting, signing and safe execution transport are implemented and verified through `toy`.

The macOS `kern.memorystatus_level` percentage is not a byte admission measurement: Apple's macOS XNU accounting includes active and inactive memory. It must not be multiplied by physical RAM to claim free capacity. Resource admission requires a separately specified conservative byte measurement, normal pressure, stable swap, the sealed ceiling plus margin and the exclusive heavy lease. The current percentage observations are host snapshots only.
