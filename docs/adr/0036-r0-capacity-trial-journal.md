# ADR 0036: R0 capacity-trial journal ownership

R0.07 needs a separate UTC-anchored 168-hour arm and every one of its 3,360 opportunities at 180-second spacing. The existing aggregate cadence read model and model-call accounting owner cannot write those identities. Durable admission/Turn Review in Self-Improvement owns the sole `toy_si.cadence_slot`; Ops and Obligations consume projections.

The bounded public interface is `CapacityTrialJournal.withTest(context, callback)`. It admits only an owned ready fake-clock/fake-model stack and uses the existing real PostgreSQL lifecycle. The generated `CapacityTrialJournalApi` exposes `startArm`, `deferSlot`, `reconcileArm`, `reportArm` and single-slot readback. All inputs and outputs come from `@toy/contracts`.

`startArm` validates an immutable arm/configuration/route/host/workload manifest and creates its arm binding and all 3,360 rows in one transaction. The same bindings are idempotent; conflicting IDs, request IDs, overlapping windows and a reduced original cadence are refused. Rows retain canonical `(job_key, slot_at)` identities. Deletion and identity changes are refused by database triggers. `deferSlot` preserves a fixed reason during the current slot. `reconcileArm` marks elapsed scheduled opportunities missed while retaining terminal deferred, failed and missed outcomes. `reportArm` performs read-only per-arm counts and sequence checks. Arm reports never combine denominators.

The migration is generated through `toy new migration capacity-trial --module self-improvement`. Its descriptor remains disposable_only and production_allowed false. Fixture arm slots cannot carry run/review/inference references or become reviewed/swept. Their only enabled clock mode is fake_model, and reports always retain acceptanceComplete false and fullCadenceVerdict NOT_EVALUATED. This makes simulated elapsed time unable to certify AI coverage. No placeholder run/review table, second slot ledger, new provider lane, background service or Swift artifact is added.

The existing `toy probe run/show` interface owns the CLI diagnostics for AT-ops-47, AT-self-improvement-59/60 and AT-RESEARCH-REGISTER-6. Fresh native PostgreSQL readbacks verify anchored identities, conflict refusal, retained outcomes and restart. Source checks and filtered diagnostics never pass the complete seven-day assertions. Each canonical CheckView prerequisite is bounded to 2,000 characters; reports must be preserved as individual bounded observations rather than combined into an oversized receipt. The current final experimental-arm receipt exceeds that bound and remains a recorded three-attempt replan.

Before production, R0.05 must provide canonical run/review foreign-key targets and the accepted current Turn Review transition. Before a live arm, R0.01 supported-route/auth evidence, R0.03 independent refresh, R0.05 actual-role/send enforcement and R0.06 accounting must pass. The original Sol/max/Fast arm then needs its own actual 168 hours, representative traffic, usage/latency/host evidence and all 3,360 accepted reviews before their next boundaries. Reduced experiments remain separate and cannot select R1 policy. Live trial start and whole acceptance remain pending.

The final experimental and original comparisons use separate canonical CheckView observations, each carrying one complete public report. Fresh CLI proof verifies all fourteen diagnostics and a 1678-character maximum prerequisite without widening the existing 2000-character evidence boundary. The unfiltered AT and live trial remain incomplete.

Fresh unfiltered commands for the four existing journal IDs return REGISTERED_CASE_NOT_IMPLEMENTED. The bounded routing interface allows omitted caseId only for AT-ops-47, AT-self-improvement-59/60 and AT-RESEARCH-REGISTER-6 at ReplayEnvironment, capacityTrialProbe and the FixtureProbe observation boundary. Four generated source-bound manifests identify the existing capacity-trial phase; the owner validates that binding before running the unchanged fourteen diagnostics. Original request identity and explicit-case routing remain intact. The same real PostgreSQL journal and external fake clock are used. Reports always retain NOT_IMPLEMENTED/complete=false, fake_model, zero live sends and no live arm; no elapsed trial, canonical run/review, provider or role prerequisite is promoted. No DTO, command, ledger, service or migration changes.
