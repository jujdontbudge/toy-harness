# Contract generation and static policy

The existing Zod schemas under `packages/contracts/src/` remain the canonical schema definitions. The current `schemaInventory` names existing primitive values from `public.ts` for generation; it does not create alternate schemas. UUID and fixed-millisecond Instant schemas encode their canonical widths (36 and 24 characters) directly, and the generated schemas carry those same length bounds alongside their patterns. The decimal maximum used by `uint64Schema` is named once and shared with the JSON Schema generator. The generated uint64 pattern accepts canonical nonnegative decimal strings through `18446744073709551615`, preserving the source refinement exactly. Digest and revision constraints use strict end-of-input checks so JavaScript's `$` before a final newline cannot admit noncanonical values. The generator passes explicit Draft 2020-12, output-mode and throw-on-unrepresentable options to each Zod JSON Schema export, then compares emitted string patterns, lengths, and enums with the public runtime schemas on fixed canonical, newline, and numeric-boundary cases.

`scripts/generate-contracts.mjs` compiles the contracts owner and projects its named schemas into generated TypeScript aliases, Python static types, Swift static types, and one Draft 2020-12 JSON Schema artifact per primitive. The current generator accepts string schemas with optional format, pattern, length constraints, and one string enum (`ModuleId`). It fails closed on object, array, numeric, boolean, null, or union schemas until their Python and Swift DTO projections are implemented. Python and Swift types preserve supported wire shapes; Zod remains the runtime validator. `npm run contracts:check` compares every generated file byte for byte with fresh output and rejects orphaned generated schema artifacts.

The static policy uses language tokenizers or parsers to distinguish comments and debt-marker identifiers from string contents. A file may contain one SPDX license identifier at its header. Only paths named by `scripts/generated-artifacts.json` may contain the exact first-line generator banner. Other comments, suppression directives, and debt markers fail. TypeScript lint rejects explicit `any`, unsafe operations, unchecked casts, non-null assertions, and floating promises. JavaScript source under `packages/`, `cli/`, `plugins/toy/`, `behavior/`, or `tests/` is rejected; only `scripts/` and `eslint.config.mjs` may use JavaScript for tooling. Those tooling files receive type-aware floating-promise and misused-promise lint, but `scripts/tsconfig.json` has `checkJs: false` and ESLint disables no-unsafe rules for JavaScript. Strict type checking of JavaScript tooling remains an explicit gap; this policy does not claim otherwise. Python strict checking and Ruff run with AST rules for `Any` and `cast`. Contract names derive from `schemaInventory`; matching structural DTO copies and exported wire DTO declarations outside contracts source/generated surfaces fail. Test files must declare `.sim`, `.cli`, `.module`, or `.internal` before `.test`/`.spec`; internal tests require a same-ID `{id, rung: INT, justification}` row in `tests/registry.yaml`. The registry uses JSON syntax, which is a YAML-compatible subset and allows validation without adding a parser dependency.

The bootstrap gate is `npm run check:k2`, currently run as `kitchen.bootstrap.static`. It runs local static operations before the control CLI exists, injects fixed lint/compiler/codegen/registry fixtures, records full sanitized command diagnostics plus policy/generator source, generated-code, and generated-schema hashes in `build/evidence/R0.K2/bootstrap.json`, and writes an immutable report under `build/evidence/R0.K2/attempts/` for each run. Fixture cleanup removes only files created exclusively by that run and removes created directories only when empty. Contract verification invokes Swift with the installed `MacOSX26.5.sdk` explicitly because the default `MacOSX27.0.sdk` requires a newer Swift compiler than the installed CLT compiler. `scripts/static-gate.json` records the intended future `kitchen.static` route, owned by EngineeringControl and dispatched through `probe.run` for `acceptance/AT-hermes-config-101` once its K3/K4 prerequisites exist. This bootstrap receipt does not pass AT-hermes-config-101; K4 must exercise the complete CLI-driven static/codegen/map assertion.
