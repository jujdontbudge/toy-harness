# Shared diagnostic contracts

This extends the existing Contracts and Ops public boundaries for K3; it adds no service, module, datastore or runtime activation. Availability and whole-AT acceptance remain separate. Sources §3.1/§4, Ops §7, CLI §4.2/§4.4/§5.1 and Self-Improvement's canonical cadence-state amendment provide the defined wire shapes.

The CLI declaration inventory is independent of CLI envelopes. It holds command IDs, arguments and metadata, and imports only primitives. Evidence/diagnostic schemas can reference the same registered command enum without a cycle through envelopes. The single release enum lives in primitives so Sources, Ops and CLI share its exact schema.

`RecordRef` and `ObservationEvidenceRef` use Life Store §4's canonical immutable wire fields: module/kind/UUID and observationRef/documentId/decimal byteFrom/byteTo/quote respectively. Older Attention excerpts use alternate evidence names; they are not a second wire contract. Owner projections and future mutations must bind the canonical immutable observation and independently verify UTF-8 spans/quotes rather than accepting a schema-valid claim as evidence. Revisions and generations remain explicit owner fields rather than becoming record identity. URI validation derives the UUID pattern from the sole primitive schema and forbids trailing bytes by exact length.

Metadata now represents canonical non-observation record references, observation evidence and operation references. `HumanInteractionRef`, owner-specific errors and all future leaf specializations are still incomplete; no owner adapter is admitted through the offline result union. Input-file authorization, response limits and protected origin registration remain separate required work.

Sources status preserves every declared field, enum and null distinction. Its `HealthState` is the Sources enum; Ops' differently scoped service state is declared in `ServiceStatus.state` and generated as its nested type, avoiding a conflicting public alias. Ops release IDs are manifest digests, distinct from first-release tags. Actual UID/PID/boot/incarnation observations cannot be invented to fill a required service record; an unavailable owner stays null with a corresponding prerequisite probe until it can provide its safe status.

Cadence coverage uses the one canonical twelve-state enum. A finite exhaustive Zod record derives every count key from it; all counts and the nominal denominator are unsigned decimal strings. The generator projects this finite required-key record to Python/Swift object types while retaining the original declared-dialect JSON schema. Arbitrary or partial maps fail generation. Runtime owners must verify that counts partition each interval, that required policy remains 180 seconds, and that only accepted Turn Review counts reviewed; the schema alone certifies none of these predicates.

`ControlStatusInputV1` contains optional release selection; `DoctorInputV1` adds the explicit deep boolean. The owner chooses the installed/attested release, falling back to R0 prerequisites only when no release is installed. `DoctorReportV1` preserves every registered check, links, complete flag and the canonical acceptance verdict; only Ops derives that verdict, with measured failure taking precedence over missing coverage. Read-only diagnostics never start inference, logins, sync, dispatch, backups or repairs.

Attention's source specifies the required snapshot content but omits a complete `AttentionSnapshot` declaration. ADR 0007 now defines its strict safe owner read projection and publisher compatibility, and Contracts composes the full `ControlStatusV1`. The snapshot keeps explicit latch, Focus cycle, effective gate/reason/epoch, stale concern, authenticated event, local cancellation and retrospective wearable confirmation separate, with bounded item/channel/local-plan views. No Attention runtime result is supplied by this declaration. ADR 0008 defines Ops' truthful unavailable-state bootstrap reads; installed owner transports remain pending.

The local `toy-control` skill is an exact extraction of CLI §7. Its receipt proves source bytes only. K4a's protected registered static/public receipt, manifest entry and reference verification remain pending; its guidance cannot authorize a production operation or imply that listed future commands work.
