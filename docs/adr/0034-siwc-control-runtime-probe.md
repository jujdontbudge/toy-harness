# ADR 0034: fixed actual-control SIWC runtime root probe

Owner: Ops. Scope: one root-request diagnostic for R0.04 and R0.01; no service activation or credential write.

`SiwcControlRuntimeProbe.run()` is the fixed repository root operation in `scripts/probe-siwc-control-runtime.mts`. Its command arguments are exactly a request UUID, artifact digest and expected compiled-child digest. It requires the already-root macOS caller and verifies the existing staged artifact through the sole staging verifier before changing anything. That verifier rejects ACLs across fixed parents, the release/manifest and every immutable inventory entry in bounded macOS permission-listing batches before executing any staged runtime. The probe then checks measured control-identity traversal bits on every unchanged ancestor. It creates a new request directory and root-only generated backup journal containing the prior numeric metadata and original bootstrap receipt digest, then seals the fixed compiled child there. No existing artifact is overwritten or adopted.

The operation temporarily changes only the existing root:root `control` and `control/releases` parent modes from `0700` to `0711`, allowing traversal without directory listing or write access. The prepared read-only plan's proposed `0710` with root GID0 would still deny UID/GID310; `0711` preserves ownership and allows the actual control consumer to reach its group-readable frozen payload. All original numeric parent metadata is restored in `finally`, with inode/device checks and independent readback. A restore failure is a blocked result, never a diagnostic pass.

SIGINT, SIGTERM, SIGHUP, SIGQUIT and SIGTSTP handlers are installed before preparation. During the asynchronous child operation they terminate the child and enter the restoration path before emitting a failure. The operation flushes pending signals before opening the parents. Uncatchable termination or power loss requires the executing root operator to rerun the same three arguments with the sole optional fourth argument `restore`. That branch validates the root-only backup, fixed request/artifact/child/receipt digests and original parent inodes, restores both modes to `0700`, and emits a distinct `restored` report. It launches no child and makes no Keychain call or artifact change. A restore report never proves the read diagnostic or an AT.

The fixed child begins as root using the copied pinned Node executable, replaces supplementary groups, sets the measured control GID/UID, and verifies real/effective UID/GID/groups before importing the frozen Secrets public module. It checks the expected factory exports without starting authorization or inference. It then invokes only the exact frozen Python helper's `read` operation with isolated Python and all three standard descriptors ignored. Keychain output bytes go directly to the OS discard descriptor; Node, the root parent, logs and model context never receive them. Exit0 means present, exit3 means absent, and every other result means unavailable.

The generated `SiwcControlRuntimeReceiptV1`, `SiwcControlRuntimeBackupV1` and `SiwcControlRuntimeReportV1` are the sole wire contracts. Reports include numeric identity, import/read availability, exact artifact/child/backup/receipt digests and restoration booleans. The operation retains its new sealed child, backup and public report, preserves all prior accounts, files, services, profiles, pointers and credentials, and makes zero provider sends. Native read availability does not prove Keychain write/refresh, supported account consent, a running protected service, maintenance recovery or any whole assigned AT. Subsequent installation remains separately scoped.
