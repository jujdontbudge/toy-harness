# K3 public CLI boundary

K3 implements CLI-01–03 from cli.md and calls only the administrative public interfaces in its §6. Input/output definitions, leaf identifiers, argument metadata, owner/access/release metadata and errors belong to `@toy/contracts`. Every leaf in cli.md §5 remains discoverable, including later-release leaves with truthful NOT_IMPLEMENTED state. The CLI performs parsing, validation, authenticated transport selection and rendering. It cannot read/write owner databases or call providers, privileged launchers or test assertions directly.

The compiled ESM executable uses Node 24.21.0's strict `util.parseArgs` tokens to reject duplicate singular options, unknown options, malformed positional counts and incompatible environment selections. Help/version require neither a stack nor network. Error messages use fixed safe text and never echo input values. Unknown release/command/schema, missing test stack, caller actor/proof/identity options and production test operations fail before transport selection. Terminal control characters are escaped in human rendering. JSON rendering uses the generated strict envelope without ANSI text.

Introspection adds two concrete owner schemas: `CliHelpV1` carries the optional registered group path, complete command/argument/schema inventory, schema digest and package compatibility; `CliVersionV1` carries CLI/contracts versions, executable/package/schema digests and explicit accepted wire versions. Unavailable future owners cannot return a success value through a permissive JSON placeholder. Their declared operation and required schema are retained as incomplete work until the corresponding strict owner schema is implemented.

Ops owns `OpsControlRead.status/doctor` and `OpsTestStack.up/down`. The existing protected evaluator/test controller owns clock/probe dispatch and assertions. Self-Repair engineering owns static/codegen/map/generator operations. Their requests/results are registered before adapters compile. Fixed test-case manifests select executable closures and external-seam faults; callers cannot choose argv, environments, SQL, endpoints, UIDs or fixture expectations. Missing service identity, native sandbox launcher, current attestation or resource permit blocks the dependent operation. Partial readiness cannot pass AT-cli-4/6/10 or actual identity gates.

K1–K3 and K4a's four enumerated references are the only hand-built bootstrap exemptions. No runtime product or R1 owner substitutes for an unavailable operation. Full K3 acceptance requires a real owned temporary PostgreSQL/process/fake-provider stack and independent restart/cleanup receipts; syntax and help checks alone cannot close it. Actual service-UID and native-launcher predicates remain explicitly pending R0.04–05, without simulated identity evidence. This document freezes the implementation boundary and makes no runtime or deployment claim.

The first executable checkpoint exported the complete declaration inventory, concrete `help`/`version` schemas and fail-closed pre-dispatch results. The diagnostic increment adds strict `status`/`doctor` schemas and the existing Ops public read interface's unavailable-state report. Canonical record/evidence and operation references are now declared. Human-interaction references and owner-specific error extensions remain incomplete; no guarded owner result adapter is admitted. Authenticated non-null owner transports, installed manifest/release discovery and future command schemas remain pending.

The sole generator hashes an ordered list of generated JSON-schema artifact paths and their SHA-256 values; SHA-256 of the compact UTF-8 JSON list is `schemaBundleDigest`. The generated compiled constant and schema artifacts are packaged together. The CLI executable digest hashes the exact `dist/main.js` bytes; its package digest hashes the compact ordered path/digest list for `dist/main.js` and `package.json`, the two admitted CLI package files. Contracts and schemas have their separate version/digest. These digests identify the offline bytes; they are not publisher attestation, installed-release or deployment proof.

The generated TypeScript/Python/Swift DTOs carry static wire shapes, literals and null/presence distinctions. Their decoders do not replace runtime validation by the exact declared-dialect JSON schemas. Python/Swift consumer validation and round-trip agreement remain pending R0.10/R1. Exclusive unions, unconstrained records, references and unsupported projections fail generation; finite canonical slot-state maps must be represented by their required key inventory. No unavailable future type is replaced by permissive JSON.
