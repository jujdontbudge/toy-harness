# SIWC control runtime staging

Johan's root-request workflow permits a repository script for one exact root-only operation. `SiwcControlStage.run` is exposed by `scripts/stage-siwc-control-runtime.mts` with fixed `prepare`, `stage` and `verify` operations, a request UUID and an artifact SHA256. It accepts no paths, executable, UID, code or shell command. The script's only assembly inputs are the current pinned Node, the existing standalone CPython 3.14.7 distribution, built protected Secrets code, generated contracts with their package metadata, the single pinned Zod and the native Keychain helper. No virtual environment is relocated.

Prepare freezes the exact file/link inventory under a private checkout build directory. Stage requires an actual root caller, revalidates the frozen artifact and bootstrap parent/receipt, then copies it into a newly allocated canonical `control/releases/<digest>/payload` directory. It seals files and directories as root-owned, read-only code with the measured control role's dedicated group. Node and isolated Python/ctypes runtime probes verify the copied executables and standalone Python relocation at the final path. Partial staging remains private and cannot be adopted or activated. Verify independently reads every artifact and ownership/mode and reruns those fixed probes; it creates nothing.

The script does not change an existing directory's mode/owner, install a daemon, switch `control/current`, open a browser, call Keychain, read a grant or send inference. The existing root-only control parent remains unchanged, so the bundle is STAGED and inaccessible to a control child until a separately backed-up, declared installation step grants only the required traversal. The retained root manifest and generated report prove staging only. Full native dependency/role/socket/credential manifest, maintenance identity, actual control launch, Keychain and provider-send enforcement remain open; no assigned whole AT is passed by preparation or staging. Swift remains deferred to R3.

Every root command and its verification is submitted in `build/ROOT-REQUESTS.md`. A pending root request never blocks the goal; independent cards continue. The artifact is frozen before submission so later source generation cannot silently change Claude's requested operation.
