# Native MCP HTTP compatibility

R0.10 exposes `HermesProfile.consumeMcpHttp(context: OpsControlContextV1): Promise<Result<HermesMcpHttpReceiptV1>>` through the assigned unfiltered AT-hermes-config-81 CLI probe. It accepts only an owned, ready R0 fake-clock/fake-model world. It accepts no endpoint, command, header, credential or transport override from callers.

The existing profile owner binds the installed Hermes commit, the reviewed MCP loader files and lockfile, and the committed environment's MCP 2.0.0 server implementation. A fresh isolated Python process hosts one fixed external endpoint using the maintained SDK's public `MCPServer.tool` and `streamable_http_app` APIs and Uvicorn's server. Its server thread shares the child process lifetime, so a CLI timeout cannot orphan a separate endpoint process. The generated `life_store` configuration contains only a loopback `/mcp` URL. The real Hermes public `register_mcp_servers`, `get_mcp_status` and `shutdown_mcp_servers` APIs consume it, discover the fixed tool and independently read connection teardown.

The external OS seam allows only the owned loopback port. All other connect/DNS attempts and subprocess effects are denied and counted. Import-time denied local binds have a separate counter. Readiness and shutdown are bounded, the server thread is joined, and child streams are discarded. The canonical receipt retains fixed configuration keys, native discovery/status/cleanup observations, process identity and counters. It contains no URL, host profile data, credentials or native log text.

Hermes may register its four standard resource/prompt utility tools alongside the endpoint's one fixture tool. The receipt permits only those five fixed names and requires the fixture tool, a matching public status count and a real connection. The first diagnostic reached the native process but its observation failed the original one-tool schema; source inspection identified the maintained utility registration behavior. The revised bounded observation leaves both native registration and the URL-only configuration unchanged.

The second observation confirms HTTP connection, all five names, six loopback connections and complete native/endpoint cleanup. It records one denied subprocess attempt. The OS audit raises before every subprocess launch, so a denied attempt is retained evidence of a refusal rather than evidence of a launched child. The acceptance predicate requires the assigned HTTP behavior and zero outside network attempts; it does not require the library to make zero requests that the OS seam already denies. The denial mechanism remains unchanged.

This unit establishes disposable native HTTP compatibility under the builder's actual identity. Live Life Store, its data/authentication, protected publication and service-role execution remain assigned to later owners. The receipt and whole AT/card acceptance remain incomplete. No protocol implementation, new service or Swift compilation is introduced. The source unit stops after its assigned diagnostic passes, or after three failed attempts with a factual replan, within a two-hour timebox.
