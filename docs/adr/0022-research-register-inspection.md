# R0.02 research register inspection

R0.01 has started. Its protected credential binding and live provider verification remain pending. R0.02 can independently expose the current research register through the control CLI without starting a stack, installing dependencies or using an account.

Public interface: `EngineeringControl.checkResearch(MapCheckInputV1, OpsControlContextV1) -> Result<ResearchRegisterInspectionV1>`, reached through `toy research check [--release R0…R5] --json`. The existing SelfImprovement engineering owner reads the fixed sibling planning checkout. Callers cannot supply file paths, research receipts, digests or admission overrides. The command performs no writes and launches no providers or workers.

The result includes every component row in inventory section 4, its source line and digest, the five register obligations, report-index file digests, and precise structural gaps. Four-cell native-package and in-house rows retain their combined consumer/research citation; their group-level missing final source digest remains explicit. The requested release is a view label; it does not erase conditional or later-release components. Malformed or duplicate rows fail inspection rather than disappear. Report presence is evidence of file availability only.

The same read-only interface now includes `specReferences`: one path/digest per flat `specs/*.md` source, explicit research-component reference IDs with exact source lines, and raw first-column cells/row digests from requirement-mapping tables. Unmapped component references become `COMPONENT_REFERENCE_UNMAPPED` findings with the exact source path and line. Files and directory enumeration reject symlinks and remain fixed to the sibling planning checkout. This source audit does not infer that every technology named in prose is selected or that ambiguous short IDs always denote a component. `dependencyClosureVerified` is structurally false; complete selected-dependency mapping, authoritative requirement-ID reconciliation and research/admission certification remain pending. A source reference scan cannot silently become a gate pass.

Admission stays BLOCKED and acceptanceComplete stays false. Inventory inspection does not establish complete dependency closure, resolved artifact integrity, compatibility probes, a gate receipt, verified primary citations or the required authenticated Sol/medium/Fast research run with a pinned loaded mattpocock skill. Those missing proofs are reported separately. Source bytes and their hashes remain available for later admission validation, which must consume the integration-owned gates described in RESEARCH-REGISTER.md rather than accepting caller assertions.

This bounded preparation changes canonical TypeScript contracts, the existing engineering owner, the thin CLI adapter and feature facts together; generated TypeScript/Python artifacts follow. Swift is deferred to R3. Verification uses the actual CLI: the current register is inventoried, unresolved components and absent certification block admission, and invalid arguments are rejected. Whole R0.02 assigned ATs, mutation cases, connector closure and protected research runs remain pending and receive no PASS from these preparation checks.
