# ADR 0019: fixed R0 fixture stack

Status: implementation available with static and packed public-CLI lifecycle receipts, 2026-10-05. Written interface precedes the owner implementation. This replaces the speculative kitchen lifecycle implementation in ADR 0010 for trusted R0 feasibility fixtures; signed target execution remains pending its assigned acceptance cards.

OpsTestStack.up/down owns a fixed fake-provider process and private SQLite world. TestClockControl.get/freeze/advance/resume owns the persisted fake clock. ReplayEnvironment.runRegisteredProbe/registeredProbeStatus selects only fixed registered owner cases. The CLI validates and wraps these public interfaces; it never receives a path, endpoint, executable, SQL, actor identity, credential or caller expectation.

The R0 world contains trusted compiled feasibility code, no model inference, no live provider and no production store. An owner-created private root, immutable request/stack/artifact binding and generated record identify it. A fixed Node process opens a real temporary SQLite database and records process/database heartbeats. Fixed external fake-provider receipts follow in K4a. Node filesystem permissions limit ordinary reads to the compiled closure, package-resolution aliases and private world, and ordinary writes to the private world. Node's permission model does not confine SQLite or establish a security sandbox. Child execution, workers and native addons receive no permissions. Its environment has no production HOME, provider variables or credentials. This is not a malicious-candidate sandbox or protected service-UID proof; those AT predicates remain pending R0.04–05. Untrusted, supported-model, non-R0 and real-clock requests remain unavailable.

Stack requests are idempotent through the owner store; changed inputs under one request ID conflict. Existing immutable blocked bootstrap requests remain unchanged. Clock mutations transact in the real test database, use distinct revision/request identities, and never alter real time or quota. Probe receipts bind the source assertion, fixed case and artifact manifest; subset receipts never pass a whole AT.

The fixed process watches only its own database for a stop request and has a bounded real lifetime. It starts in its own session so it survives a completed launching CLI session. Teardown requests cooperative stop and verifies the recorded process is absent before declaring it complete, including an already absent process with a stale heartbeat. It never sends a signal to a remembered numeric PID. Unknown ownership or a substituted root/database refuses cleanup. Test files and permitted receipts are retained; production paths and services are outside the selected world. Readiness keeps all unimplemented later owners visible.

Two actual startup failures required bounded launcher diagnosis: Node package resolution read the workspace symlink alias's package metadata, and the first process shared the completed CLI session. The fixed launcher now admits the compiled package-resolution aliases and detaches its session. Diagnostic stderr is capped, classified and discarded; only a finite failure code and safe package-metadata locator reach the CLI. No kernel/ABI investigation or additional native protocol was added. Clock advance stores its whole operation envelope so retries preserve the actual acceptance timestamp.

Acceptance is driven through the compiled `toy` CLI: up/retry, named status/doctor, fake clock/revision/idempotency, fixed probe run/show, down/retry and fresh-generation restart. Production mutations, foreign stacks, changed requests, unregistered selectors and executable/SQL/identity flags deny before dispatch. Exact service-identity/confinement assertions and full SIM remain pending by their existing IDs, never represented as passed by these fixture observations.
