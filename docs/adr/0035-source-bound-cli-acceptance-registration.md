# Source-bound CLI acceptance registration

The registered AT85 public interface remains `toy --env test --stack <UUID> probe run AT-hermes-config-85 --request-id <UUID> --json`, followed by `probe show <operation-id>`. A case filter is a diagnostic subset. No new test runner, transport or module is introduced.

`tests/registry.yaml` is the authored JSON-compatible YAML inventory. Its existing INT rows retain exactly `id`, `rung` and `justification`. A CLI row supplies the TEST-PLAN fields `id`, `rung`, `sourceAssertionHash`, `commandId`, `scenarioId`, `owner`, `firstRelease`, `kind`, `mandatoryCases`, `trigger`, `faultControls`, `observations` and `simUnavailableReason`. The first concrete row is AT-hermes-config-85, owned by Hermes at R0, with scenario `auth.fresh-process`. Its five mandatory public subprocess phases are add, list, fresh chat, expired-grant refresh chat and post-refresh fresh chat. Runtime help is a prerequisite rather than a sixth behavioral denominator cell.

The canonical `RegisteredCliAcceptanceManifestV1` contract describes that authored CLI row. Every mandatory case records a fixed identifier, public operation and observation phase; trigger and SIM-unavailable reason are bounded text; each external fault records a fixed identifier, seam and affected phase; each observation records a fixed identifier, independent reader and covered case identifiers. Required observations bind process exit/identity, exact public argv, external provider ledger, root/profile-store readback, token hygiene and fresh-process usability. No caller-supplied executable, SQL, provider endpoint, identity, grant or expected verdict enters the interface.

The sole contracts generator joins authored CLI rows to the exact source-indexed AT ID, assertion hash and release. It rejects stale hashes, duplicate IDs, dangling cases/observations, unknown owners or unregistered row fields before writing the generated probe inventory. Generation first compiles the canonical contracts, validates every authored manifest through that public schema, writes the registry, then compiles its consumers and emits the artifacts. The registry-only stage applies the same canonical validation; it has no weaker handwritten parser. The existing registry lint checks CLI metadata alongside its INT reachability obligations. Missing CLI rows remain unimplemented; publishing one row never manufactures registrations for another AT. Generated DTOs and schema artifacts remain TypeScript and Python only until R3.

The existing probe report exposes this authored metadata in optional `sourceRegistration`, keeping historical receipts readable. Its case-manifest digest binds the metadata and the exact fixed scenario beside the existing source/artifact bindings. This read-only projection does not dispatch a behavioral operation or change the report's NOT_IMPLEMENTED/complete-false verdict. Mandatory-case entries use `{id, publicOperation, phase}`, faults use `{id, seam, affectedPhases}`, and observations use `{id, independentReader, caseIds}`. The first registration must name Hermes, `auth.fresh-process`, and all five required phases; a structurally valid partial or wrong-owner row cannot stand in for AT85.

This source registration does not grant acceptance authority. The protected controller must later verify the exact sealed owner/import closure and manifest, execute through the actual intended Ops/evaluator/agent role path, require every mandatory observation exactly once, and independently read the fixture effects and root/profile stores before aggregating a whole-AT verdict. Ordinary caller diagnostics currently use UID501 and cannot certify a service UID. Unfiltered AT85 currently returns NOT_IMPLEMENTED, confirmed by a real run/show in a fully cleaned-up world. Root-request02 remains an independent frozen Keychain-read operation; this unit neither modifies it nor claims native launcher, controller transport, sandbox or account admission.

The existing CLI gardener static gate supplies wrong-owner and missing-phase source fixtures and requires their rejection before any generated registry change, then restores both authored and generated files with identity/content checks. The wrong-owner fixture reproduced an accepted write before canonical validation moved ahead of generation. Its compiler negative uses the pinned TypeScript5.9.3 flags and checks the intended unchecked-index diagnostic.
